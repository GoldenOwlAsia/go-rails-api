# Models and migrations

## Models

- The `# == Schema Information` header is generated by annotaterb after `db:migrate`
  in development (`lib/tasks/annotate_rb.rake`), and it also rewrites the matching
  factory and serializer. Do not hand-edit it. Expect those files in the diff.
- Primary keys are UUIDs (`gen_random_uuid()`) and no model sets
  `implicit_order_column`, so `first`, `last` and every page order by a random value.
  Anything whose order matters must call `.order(...)`.
- `.rubocop.yml` enforces `Layout/ClassStructure`: includes, constants, attribute
  macros, associations, scopes, validations, delegations, callbacks, then methods.
- Shared values such as content types and size limits live in
  `config/initializers/constants.rb`, not in the model that needs them.
- Callbacks are for normalization and defaults only. A callback that sends mail,
  enqueues a job, calls an API or creates a related record is a workflow and belongs
  in an operation. `spec/architecture_spec.rb` fails on mail or job dispatch in
  `app/models`.
- A validation that promises an invariant (`presence`, `uniqueness`) needs the matching
  constraint (`null: false`, a unique index). A model-only promise is a race. No gem
  checks this here, so check it yourself.
- Validate attachments with `active_storage_validations`, as `User#avatar` does.

## Migrations (`db/migrate`)

Append a new migration; never edit one that has been committed. This app has no
`strong_migrations` or `good_migrations`, so nothing checks migration safety. Locks,
rewrites and backfills are yours to reason about.

- Generators already default to UUID primary keys. Reference with `type: :uuid`, or the
  foreign key column comes out as a `bigint` that cannot hold the id.
- Never reference an application model from a migration: it will not match the schema
  at that point in history.
- Adding an index to an existing table needs `disable_ddl_transaction!` plus
  `algorithm: :concurrently`. Inside `create_table` it does not.
- Split schema changes from large data backfills into separate migrations.
- Avoid table rewrites and long exclusive locks, such as changing a column type.
- Add foreign keys for every `belongs_to`.
- A unique index over a nullable column does not constrain the rows where it is `NULL`.
  Pass `nulls_not_distinct: true` (PostgreSQL 15+) when those rows must be unique too.
- A case-insensitive uniqueness validation needs an index on `lower(column)`.
- Write a reversible `change`, or explicit `up` and `down`.

### Verify

- `bin/rails db:migrate:status`: no `NO FILE` entries
- `git diff db/schema.rb`: only the intended change
- `bundle exec rubocop db/migrate`
- `bundle exec rspec` on the specs touching those tables
